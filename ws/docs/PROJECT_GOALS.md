# 项目目标与研究方向

本页记录项目的长期目标、设计原则与架构设想，是讨论路线、接口和研究方案的依据；具体实现在动手前讨论确定。2026-10-19 起草，2026-10-31 补充模块化实现与开发边界。推进顺序见 [项目计划](PROJECT_PLAN.md)。

**定位**：实验平台是 NVIDIA 开源的 Isaac Lab-Arena × GR00T N1.6 G1 移动操作 demo（见 [平台设计](platform/G1_DESIGN.md)），它只是起点。项目的工作是把它逐步改造成本页的架构，改造过程中平台原有的骨架可能被完全替换。

## 长期目标

机器人必须能在真实环境中持续学习，而不是只靠仿真训练出一个固定的模型。同时，无论学习怎样进行，物理安全都由确定性的部分保证：AI 决定"做什么"，确定性的门阀和控制回路决定"能不能做、怎样安全地做"。

## 基本判断

一个机器人服务于一个具体场景，不会同时应付家庭、农业、医疗。在具体场景里，机器人的目标是一贯的、有限的，因此需要的能力可以显式定义，例如必须会抓握、必须会行走、必须会采摘苹果。不同场景的重点不同，技术栈也可能大不相同：

| 场景 | 重点 |
|---|---|
| 家庭 | 家庭环境的细碎与复杂、物理安全、人机交互、智能性、情绪价值、管家能力 |
| 农业 | 物理世界的随机性（泥土、天气等）、末端操作能力（摘不同的水果和收割小麦是完全不同的能力） |
| 医疗 | 绝对的安全与保守操作、感知能力、对目标的正确理解（例如"清理血栓"指的是把堵住的地方疏通，而不是字面意义上的清空） |

## 适用范围与前提

暂不考虑极端复杂、极其危险的场景（例如复杂环境中的高速自主行驶）。前提是机器人存在一个安全状态：原地待机就能化解所有安全问题。

## 设计原则

1. **AI 不进入控制管线。** AI 只负责外部模块：感知环境、决定现在要做什么，并把决策编排成各部件的指令。把指令变成执行器输出的控制回路是确定性的，以高速控制周期持续运行，不受 AI 推理延迟的影响。
2. **决策要经过审议。** 多个 AI 专家、云端模型或人类协同判定一个决策是否合理。不合理的决策被否决，并受到严厉惩罚。例如 AI 提出"无视前方的儿童，以某种方式前进"，这必须被否决。
3. **物理安全由确定性的门阀与审计模块推演。** 例如计算机器人离摔倒还差多少：如果执行某个动作后，一个小于阈值的突发外力就能把机器人推倒，这个动作被否决。被否决的动作不执行，确定性逻辑立即接管，否决本身记为惩罚。
4. **学习在真实环境中持续进行，除非显式固化。** 奖励由人类设计。
5. **固定的能力集锚定机器人。** 机器人要时时用这套能力自检，防止遗忘和漂移。

## 分层架构（设想）

| 层 | 做什么 | 性质 | 频率量级 |
|---|---|---|---|
| 决策层（AI 模块 1） | 感知环境，决定现在要做什么 | 学习型，可持续微调 | 秒级 |
| 审议层 | 多个 AI 专家、云端或人类判定决策是否合理，否决并惩罚 | AI 与人协同 | 秒级 |
| 编排层（AI 模块 2 + 确定性逻辑） | 把决策同步成各部件对应的指令 | 学习型与确定性结合 | 十赫兹级 |
| 安全门阀与审计 | 推演物理安全：稳定裕度、碰撞、力与速度限制；否决或降级 | 确定性 | 每个控制周期 |
| 控制核心 | 输出各部件的确定性指令，持续高频运行 | 确定性 | 数百赫兹到千赫兹 |
| 执行器驱动 | 电流环、PWM、高低电平 | 驱动器固件 | 千赫兹以上 |

各层的具体设想：

- **决策层**：只关注感知自身和环境，判断是否要发布决策、发布什么决策，不关心能力怎样组合。它至少由两个网络组成：决策制定者和调用者。调用者持续判定当前需求，分发给若干专家，专家参与制订决策。机器人的能力集显式固定，每个 AI 专家只负责其中一项能力；要增加新能力，插上一个新专家，调用者就能自动路由，能力因此可以热插拔。决策层只在决策违反原则、或与当前激活的决策冲突时否决，例如当前激活的决策是"以 10 m/s 前进"，在不撤销它的情况下又发布"静止"。
- **审议层**：跳出机器人本位，转向环境视角和风险估量，判断一个行为对周围的人、物和环境意味着什么。它的作用是提供好的奖惩，让机器人的行为不产生偏移。
- **编排层**：由一个掌握硬件确定性知识库的专家 AI 担任，负责能力的组合，向所有硬件下发确定性的动作目标。这些目标是封装好的 API 调用，例如"向腿部关节和左脚发布柔顺控制命令"。如果一个决策通过了审议、却在编排时发现实际冲突，编排层提交否决提议，以确定性策略维稳，等待新的决策，并对决策层和审议层施加惩罚。这种情况极其特殊，一般不会发生。
- **安全门阀与审计**：对这些 API 调用严格审计、推演物理后果，通过后才执行。
- **控制核心**：怎样精确实现 API 调用由确定性的精密控制决定，不涉及 AI。各能力在动力学上的耦合（例如走路会改变手臂的动力学）也在这里处理。

**架构变异**：如果某项能力确实必须依赖 AI 深度集成控制才能实现，就让架构只在这一处变异：决策层一旦下发这项能力的决策，就走另一条管线，确保只影响这一项能力。

学习只发生在决策层和编排层。学习信号来自三处：人类设计的奖励、审议层与安全门阀的否决（作为惩罚）、能力自检的结果。门阀和控制核心不学习，行为可以测试和验证。

在 Unitree G1 这类机器人上，PWM 和电流环由电机驱动器的固件完成，控制核心输出的是关节级指令（位置、速度、力矩和增益）；具体频率与接口在接入真机时核实。

## 模块化实现（设想）

2026-10-31 补充。上面的分层架构落到软件上，是一套可热插拔的模块化结构，类似高内聚、低耦合的微服务：

- **部件即模块。** 腿、手臂、手、感知、上层 AI 等各是一个模块，各自把能执行的动作集注册到中央调度器。模块之间通过 ROS 2 通信；上层 AI 也只是其中一个模块，可以整体替换。
- **中央调度器按事件下令。** 平时基本空闲，遇到突发情况时能迅速下达指令；衡量它的指标是反应延迟，而不是发指令的频率。离散的技能指令（开始抓取、停下、换目标）走带反馈和取消的 RPC（ROS 2 action），高频的连续设定值走话题或留在进程内部。
- **按时间尺度划进程边界。** 慢的模块（VLA、决策、审议、审计）是独立节点，可以随时替换；快的控制回路（真机关节控制约 500 Hz–1 kHz）放在同一个实时进程里，以插件形式热插拔，即 ros2_control 的做法，也与"控制核心做成 C++ 动态库"一致。
- **稳定守护进程。** 一个始终运行的进程负责在任何时刻维持平衡：腿部高频地对重心的意外变化做出反馈，不关心是什么改变了重心；安全门阀限制重心变化的速度。部件之间因此不必严密耦合。为了不只是事后补偿，部件在动作前可以通过一条前馈通道告知"将要产生多大的负载或重心偏移"，守护进程提前调整，相当于人的预期性姿态调整。需要协调动作时，由调度器明确告诉守护进程暂不反馈。
- **分层安全，各层时间尺度不同。**
  1. 决策质量（秒级）：上层决策是否合理。违背原则的指令（例如"撞向那个小孩"）被否决并严厉惩罚；有更好办法时却选择"紧急停止"，评分相对较低。
  2. 映射质量（数十毫秒）：中层模型或专家是否把决策合理地映射到各部件的动作集；用简化模型的 MPC 预测协调动作的稳定裕度与可行性，即受到多大干扰会失稳。
  3. 部件反射（毫秒级）：每个部件有一条经过验证、直通上层的反馈路径。突然宕机、电池松动、被高速物体击中时，先由部件本地的反射立即处理，调度器再在数十到上百毫秒内发布全身的新预案。
  安全门阀位于所有指令通往执行器的路上，而不是旁路观察。
- **失效处理暂缓设计，但不会省略。** 机器人不能像网络服务那样靠重试；接口里先预留"进入安全状态"的入口。

和分层架构的对应：中央调度器承担编排层；各部件的执行器与稳定守护进程属于控制核心；三层安全对应审议层与安全门阀。

## 开发边界

2026-10-31 确定：

1. **上层 VLA 当作现成部件。** 不研究模型本身的实现与优化（纯 AI 方向），只关注它与其他模块的交互方式：输入、输出、时序。有现成的新 VLA 时再做适配；深入上层 AI 的设计留到更后期。VLA 只看缩小后的单帧画面，并且是针对固定相机视角微调的，因此视觉方面的投入优先服务确定性层（物体位姿、人与障碍物检测、抓取状态），改变 VLA 的输入需要重新微调。
2. **VLA 不直接控制电机。** 它输出任务层面的意图（手要去哪、往哪走），由确定性的逆运动学与全身控制换算成关节指令，审计与否决位于这一层。

## 与平台的差距

平台和上面的架构有三处根本不同：

- **GR00T 直接输出关节目标**（每次 50 步），手臂和手的目标每 1/50 秒直接交给关节 PD 控制器，相当于 AI 在关节层面直接控制上身，中间没有确定性的门阀。平台已有以手腕位姿为输入的逆运动学接口（遥操作用），训练数据也记录了手腕位姿动作，因此改为输出手腕位姿只需要改模态配置并重新微调一次。
- **下身行走由 AGILE 强化学习网络在 50 Hz 回路里生成**，也就是 AI 在控制管线之内。它的做法本身接近上面的稳定守护进程：把手臂动作当作扰动，只管保持平衡，但没有前馈，也没有可验证的安全边界。
- **仿真等待推理。** 推理期间仿真暂停，控制回路实际上在等 AI；真机上这不成立。

长期架构下，前两处要么替换为确定性的控制（例如基于模型的 MPC 与全身控制），要么作为显式固化、经过测试的能力放在门阀之内。选哪种是下面的第一个开放问题。

## 开放问题

每一项在动手前讨论：

1. 显式固化、经过测试的学习型控制器（例如 RL 行走策略）能否留在确定性层内？还是行走也必须用基于模型的控制？
2. 编排层输出到哪一级：末端目标、落脚点、速度指令，还是技能参数？这是[项目计划](PROJECT_PLAN.md)中接口契约要回答的问题。
3. 时间紧迫的情况（例如儿童突然出现）不能等审议，必须由确定性规则独立处理。而感知本身是 AI，漏检时怎么办？是否需要与语义无关的冗余检测，例如基于距离的障碍检测？
4. 稳定裕度怎样实时计算：倒地前能承受的最小外力、捕获点等基于简化模型的指标。这部分与控制理论学习线衔接。
5. 真机自检怎样低成本地进行：复位、成败判定、自检频率。
6. 长期持续学习中的可塑性下降，以及奖励漏洞被持续优化放大。
7. 安全状态本身怎样实现：人形机器人"原地待机"也需要主动控制平衡，受推仍可能摔倒；手里拿着东西时，停下未必安全。可能需要把"维稳 / 安全停机"做成控制核心里第一项确定性、经过验证的能力，必要时过渡到下蹲等更稳定的姿态（工业上有按停机方式分级的做法，例如 IEC 60204-1 的停止类别，可作参考）。
8. 新专家怎样被自动路由：调用者需要知道新专家能做什么。一种不必重新训练调用者的方式是，专家自带能力描述（前置条件、效果、安全范围），或者在收到需求时各自给出提议和把握程度，由决策制定者挑选。
9. 变异管线的边界：AI 深度集成的那条管线替换的是编排与执行，安全门阀的硬约束和安全停机仍应保留在它下面，不被绕过。
10. 决策之间的冲突检测（例如未撤销的"前进"与"静止"）可以是确定性的规则：把激活中的决策作为显式状态，按发布、撤销、完成管理。

## 相关概念

便于定位自己的工作。以下出处凭记忆整理，引用前需核对原文。

| 概念 | 和本项目的关系 |
|---|---|
| Simplex 架构 / 运行时保障（runtime assurance） | 高性能控制器加经过验证的兜底控制器，由切换逻辑决定谁接管；对应"门阀否决后确定性逻辑接管" |
| Shielding（Alshiekh 等，2018） | 安全强化学习中，在执行前拦截不安全动作，并可给出惩罚 |
| Responsibility-Sensitive Safety（Mobileye，2017） | 自动驾驶中用确定性的形式化规则检查规划决策；对应审议与门阀对决策的否决 |
| 控制障碍函数（CBF）安全滤波 | 以最小修改把动作投影到安全集合内 |
| 捕获点与可捕获性（Pratt 等，2006） | 人形机器人平衡裕度的经典指标；对应"离摔倒还差多少" |
| Loss of plasticity（Dohare 等，Nature 2024） | 长期持续训练的网络会逐渐失去学习能力 |
| Options 框架（Sutton 等，1999） | 分层强化学习中的"技能"，带启动条件与终止条件；对应显式能力集 |
| SayCan（Ahn 等，2022）、Code as Policies（Liang 等，2022） | 大模型提出要做什么，再由可行性评估或可执行的技能 API 落地；对应决策层与编排层 |
| 双系统 VLA（GR00T N1 的 System 2 / System 1，Figure 的 Helix） | 慢的视觉语言模型加快的动作模型；与本项目的区别在于这里快的一层要求确定性、受门阀约束 |
| ros2_control | 控制器以插件形式加载，运行时可切换；对应快回路的热插拔 |
| 行为树（BehaviorTree.CPP，Nav2 使用） | 中央调度器的常见实现方式 |
| 预期性姿态调整（anticipatory postural adjustment） | 人在动作之前先调整姿态；对应稳定守护进程的前馈通道 |
| 基于二次规划的全身控制（任务优先级） | 部件间强耦合时的另一种做法，与稳定守护进程互为参照 |

## 与三个容器的对应（建议，未定）

- **policy**：决策层与编排层的 AI 模型，负责推理与持续学习。
- **sim**：数字孪生，用于安全推演、上线前测试和训练。
- **dev**：集成、ROS 通信、审议与能力测试框架；控制核心在这里开发。
- **控制核心**：安全门阀加确定性控制，以动态库形式被 sim 与真机进程加载（项目计划的真机阶段），不含学习成分。
